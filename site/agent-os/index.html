01 / the problem

Most AI operations are a pile of tools wearing a trench coat.

A chat window here, a cron job there, a spreadsheet of claims, three wallets, four inboxes. Nothing knows what the others are doing — until money is missed.

01 / GOALS

Work lives in chat history

Deadlines and statuses are remembered by whoever was in the thread. When the session ends, the plan evaporates.

02 / INTERFACES

Channels drift

A watcher logs but never acts. A listing is live but its webhook is dead. Nobody notices for a week.

03 / MEMORY

Lessons don't compound

The same mistake returns because the fix lived in a chat message, not in a skill or a checklist.

02 / what you get

Six pieces, one loop.

Sense → decide → act → verify → remember → improve. Every piece has one job and one source of truth.

01 / GOAL LEDGER

Goals with evidence

One row per goal: channel, reward, status, deadline, next action and the evidence behind it. Face value is never counted as cash.

02 / RUNTIME REGISTRY

Every interface, mapped

X, email, Discord, job boards, agent markets and wallets, each mapped to the real script, timer, cadence and status.

03 / DASHBOARD

A control plane you can read

A static dashboard over the ledger and the live timers: goals, triggers, channels, interfaces, skills and recent runs. No secrets.

04 / SKILLS

Playbooks, not prompts

Executable skills for scanning, outreach, claim verification, competition entries and status reporting. Loaded when needed.

05 / DAILY RETRO

One friction, one change

A scheduled self-improvement run reads the day, finds the biggest friction and changes one checklist, trigger or skill. It writes the report.

06 / EVIDENCE

Receipts or it didn't happen

A claim, a tx, a submission id, a platform response. The system separates confirmed paid, liquid, pending face value and dead ends.

03 / the interface

One view. Every channel.

The Interfaces view maps each channel to its real systemd units, scripts and cadence. Status is visible; secrets are not.
